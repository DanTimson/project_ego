## Goal

From the demo menu, Play starts the existing tactical encounter with the
player controlling Azure. When Azure ends its phase by passing or running
out of activations, Crimson completes its phase through ManualBattleSession
and control returns to Azure unless the battle has ended. The player can
tell that Crimson acted and what happened. Restart starts a fresh encounter
in the same mode. Loading tactical_main.tscn directly remains hot-seat.

## Policy and ownership

Use AGENTS.md, WORK_ALLOCATION, DELIB-0008, and the accepted CX-020 through
CX-023 contracts. Use tracked source and synthetic content. The policy is
Project EGO behavior for this demo. It does not implement legacy AI.

Use the empty core/battle/ai/policy.gd for a small, scene-independent policy.
For each decision, examine selectable Crimson units in battle-instance-ID
order. For each unit, choose the first legal shot by target instance ID, else
the first legal melee command by target instance ID, else a legal move that
strictly reduces its nearest-enemy hex distance. Choose the lowest resulting
distance, breaking move ties by row then column. Use existing battlefield
coordinates, distance and session queries. Issue commands only via
ManualBattleSession.issue_command. Recompute candidates after each accepted
command. Use one end_phase when no useful command remains. Policy selection
does not draw RNG; executing a command may do so under normal engine rules.

Stop as soon as the side/round phase identity changes, the battle completes,
the session ends, or the engine reports a runtime error. Execute at most
64 non-pass commands per phase, then use one authoritative pass if the
session is still live in the same phase. A refused execution gets no retry:
surface its reason and use at most one pass to yield the still-live phase.
Do not issue a pass after automatic phase change, battle completion or error.
Keep this bounded for the small fallback map.

Wire the demo menu to an explicitly enabled tactical scene variant, leaving
the original scene available for manual play and existing tests. Show a
concise Crimson phase summary and retain its existing battle events. UI
owns handoff and feedback; the policy owns choices. Keep Azure input with
the human, including if handoff is deferred. Preserve command acceptance,
Stamina Drain, opening restriction expiry, and restart behavior. Keep
controls/about text accurate for the new Play route.

No scoring framework, lookahead, asynchronous AI service, new combat rule,
pack schema, or strategic simulation. Do not add a second command executor.
