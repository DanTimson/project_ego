# CX-004 — guard populated generated bindings

## Contract

- **Class:** `NON_SEMANTIC_TOOLING`
- **State:** `DONE`
- **Semantic owner:** binary/governance
- **Executor:** Codex
- **Reviewer:** binary/governance
- **Runtime behaviour may change:** no

## Goal

Prevent accidental commitment of populated generated
`packs/*/bindings.json` files while allowing the intentionally empty skeleton.

## Non-goals

- Do not decide whether populated mappings may ever be redistributed.
- Do not alter binding generation or runtime loading.
- Do not delete local generated files.

## Authoritative inputs

- `docs/PUBLIC_LINEAGE_TRANSFER.csv`
- `docs/PUBLIC_LINEAGE_GATE.md`
- current committed binding skeletons

## Allowed inputs

- `packs/*/bindings.json`
- generator documentation sufficient to identify the empty structure
- Git index/file status when needed

## Prohibited inputs

- original game bulk data;
- generated mappings beyond what is necessary to test the guard.

## Allowed output paths

- `tools/check_generated_bindings.py`
- `tools/test_check_generated_bindings.py`
- optional `.gitignore` change only if the reviewer approves it separately
- documentation corrections limited to this task file and queue state

## Required behaviour

- parse JSON structurally;
- define the currently committed empty skeleton explicitly;
- fail on populated committed mappings;
- distinguish an absent file, empty allowed skeleton, malformed JSON and
  populated content;
- never rewrite or delete files;
- provide a narrowly scoped override only through an explicit command-line flag
  that still reports the finding.

## Acceptance

```bash
python3 tools/test_check_generated_bindings.py
python3 tools/check_generated_bindings.py
git diff --check
```

## Escalate instead of deciding when

- multiple legitimate empty schemas exist;
- a committed populated mapping is already present;
- an ignore-rule change would hide non-generated project files.

## Handoff

Report the accepted skeleton shape and every repository file checked.
