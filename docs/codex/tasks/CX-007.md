# CX-007 — repository-governance CI integration

## Contract

- **Class:** `NON_SEMANTIC_TOOLING`
- **State:** `BLOCKED`
- **Dependencies:** CX-001 through CX-005 accepted
- **Semantic owner:** binary/governance
- **Executor:** Codex
- **Reviewer:** binary/governance
- **Runtime behaviour may change:** no

## Goal

Run accepted dependency-free governance validators automatically in repository
CI without changing gameplay or release behaviour.

## Non-goals

- Do not add semantic engine tests not already accepted.
- Do not make the public-lineage gate pass automatically.
- Do not upload repository contents or reports to third parties.

## Authoritative inputs

- accepted commands from CX-001 through CX-005;
- existing repository contribution and CI conventions.

## Allowed output paths

- `.github/workflows/repository-governance.yml`
- optional local aggregate command under `tools/`
- documentation corrections limited to this task file and queue state

## Required behaviour

- run on pull requests and main-branch pushes;
- use only standard Python and checked-in scripts;
- preserve readable component failures;
- avoid network access after checkout;
- keep runtime/game test CI separate unless an existing workflow already
  combines them.

## Acceptance

```bash
python3 tools/check_deliberations.py
python3 tools/check_public_lineage.py
python3 tools/check_generated_bindings.py
python3 tools/scan_transfer_surface.py
python3 tools/public_lineage_preflight.py
git diff --check
```

## Escalate instead of deciding when

- repository branch policy or required-check naming needs a human choice;
- an accepted tool has unstable output or excessive runtime.
