## Purpose

The accepted legacy-boundary inventory and review establish that generic EGO runtime
still uses raw source modifier/opcode integers as behavioral authority after content
normalization.

CX-017 establishes the first production semantic translation boundary.

This is intentionally NOT a repository-wide migration. It introduces one reusable
passive-modifier semantic-query mechanism and migrates exactly three simple,
mechanically established raw queries as distinguishing proof:

- source modifier `0x12` -> semantic `stamina.mutation_suppressed`;
- source modifier `0x26` -> semantic `combat.melee_exchange_suppressed`;
- source modifier `0x13` -> semantic `morale.underflow_suppressed`.

The exact source numbers are legacy compatibility knowledge. They must not remain in
generic consumers after this task.

## Architectural invariant

Generic EGO runtime must not use original source modifier IDs as behavioral authority
once the source modifier has been successfully normalized.

Legacy source identity may remain in:

- pack/profile binding/import adapters;
- generated local compatibility bindings;
- diagnostics and provenance;
- compatibility tests and research evidence.

Runtime authority for migrated mechanics is an EGO-owned semantic identity.

Unknown/unresolved source modifiers remain unresolved. Do not invent semantic keys.

## Semantic identity representation

Introduce an EGO-owned typed/validated semantic-query vocabulary.

The serialized/profile-facing names for this tranche are exactly:

```text
stamina.mutation_suppressed
combat.melee_exchange_suppressed
morale.underflow_suppressed
```

Exact in-memory representation is implementation-owned, but it must be closed and
validated for engine-known semantics in this tranche. Preferred forms are an enum or
equivalent typed key, not arbitrary runtime strings scattered through rules code.

A modifier may carry zero or more semantic query identities.

Requirements:

1. Semantic identities are distinct from the source opcode.
2. Semantic identities are normalized/deduplicated deterministically.
3. Unknown semantic names in a binding fail closed with a useful diagnostic.
4. Runtime queries operate on semantic identities, not source numbers.
5. EGO-native/synthetic normalized modifier construction can specify semantic
   identities directly without any source opcode.
6. A source opcode may remain attached during this transitional migration for
   provenance and for still-unmigrated legacy behaviors, but the three migrated
   mechanics must never consult it.
7. Do not falsely declare the raw opcode globally provenance-only yet: other P0
   consumers remain for later tranches.

## Binding schema extension

Extend the existing pack binding representation with optional semantic query
metadata.

Exact JSON field name is implementation-owned; prefer a clear form such as:

```json
{
  "opcode": 18,
  "handler": "...",
  "semantics": ["stamina.mutation_suppressed"]
}
```

or repository-equivalent.

Requirements:

- pack/profile qualified;
- source opcode remains a compatibility-side key;
- zero semantics is valid;
- multiple semantics are representable;
- duplicates normalize deterministically;
- unknown semantics reject the binding rather than becoming opaque runtime strings;
- handler resolution and semantic-query resolution are independent dimensions;
- existing bindings without semantic metadata continue to load;
- unresolved/unbound opcode behavior remains unchanged;
- fingerprint/provenance does not grant semantic meaning.

Do not combine passive modifier semantics, activated action IDs, battle-action
effect opcodes, or source unit records into one bare-integer namespace.

- pack ID equality alone is not semantic authority;
- numeric coincidence across profiles is not semantic authority.
