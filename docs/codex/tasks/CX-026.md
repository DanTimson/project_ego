## Goal

Use a headless two-encounter fixture through ManualBattleSession. A wounded
Azure survivor in Ford must enter Watchpost with the same remaining life,
the same persistent roster identity, and a fresh encounter-local object
and instance ID. Keep the campaign model independent of tactical lifetime.
There is no menu or save-file format in this task.

## Native contract

- Store value-only roster entries with stable roster IDs, authored unit
  definitions, current life, and a roster revision. Begin each encounter
  from a detached snapshot, a caller-supplied encounter ID and seed, native
  profile and pinned content/rules identity, and an explicit mapping of
  roster IDs to tactical instance IDs. Reuse normalized content identity or
  fingerprinting where it fits. Each encounter gets its own tactical state.
- Build a value-only outcome from a completed, non-errored battle. Include
  encounter ID, source roster revision, content/rules identity, winner and
  final life for the mapped roster units. Only current life crosses this
  boundary. Zero life marks a casualty and excludes that unit from the next
  deployment. Battle resources, statuses, side changes and RNG stay local.
  Refuse unknown or duplicate IDs, changed ownership or identity, and
  unsupported replacement/summon outcomes rather than guessing writeback.
  Keep the synthetic fixture within the supported domain.
- Validate the entire outcome before mutating the roster. Apply an unseen
  encounter only to its matching source revision and pins, update the
  roster and store the complete receipt in one operation, and advance the
  revision once. A byte-equivalent or structurally identical retry returns
  the original receipt even after revision advances. An encounter ID
  reused with different payload or a stale unseen outcome refuses without
  partial mutation. Returned snapshots and receipts must not alias live state.
- Keep the API limited to this native in-memory boundary. Do not add
  a serialization schema, map, economy, rewards, generalized campaign
  scheduler, legacy timing, tactical rules, or UI.
