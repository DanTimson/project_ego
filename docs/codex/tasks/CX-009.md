## Authority and provenance

This task implements a human-confirmed Eador gameplay invariant supplied by the
project owner on 2026-08-09:

> A successful attack, spellcast, or activated ability normally ends that unit's
> turn/activation. Exceptions exist and must be explicit; a known example is the
> rat subtype using corpse-eating without spending its turn.

Treat this as an engine-owned compatibility requirement, **not** as newly
recovered binary evidence. Do not edit `docs/EVIDENCE_LEDGER.csv`,
`docs/REVERSE_ENGINEERING.md`, or `docs/FUNCTION_MAP.csv` to manufacture binary
provenance for it.

Existing repository evidence already establishes the surrounding scheduler
boundary: tactical combat uses whole-side phases, ordinary unit commands do not
transfer control to the opposing side, and a current-side unit may be
deselected/reselected while still eligible. Ranged-executor evidence also
records activation-capacity clearing at the executor tail. Preserve those
established facts.

## Goal

Make successful turn-consuming tactical actions terminate the **acting unit's
activation**, while keeping control with the same side until side pass or
exhaustion.

The fix must cover the live tactical command path, Python oracle, deterministic
tests/fixtures, and the manual playable tactical session. It must use the
existing action-consumption policy where possible rather than inventing a
parallel "ends turn" rules system.

## Frozen semantic rules

### 1. Unit activation, not side phase

A successful terminal action ends only the acting unit's activation.

It does **not**:

- switch `RoundLoop.active_side`;
- implicitly pass/end the current side phase;
- start a new round;
- consume another friendly unit's activation.

The current side remains in control and may select another eligible unit.

### 2. Default terminal actions

After successful resolution, the following current player-issued primary action
families are terminal:

- ordinary melee attack;
- ranged attack;
- spellcast, if represented by a distinct current executor;
- activated ability/action whose existing resolved policy says it consumes the
  action.

"Terminal" means the actor is no longer eligible for ordinary movement,
another primary attack, another spell/action, or re-selection as an actionable
unit until an accepted refresh path occurs.

The implementation must enforce this at the authoritative model/command
boundary. Merely hiding the unit in the UI is insufficient.

### 3. Movement before the action remains valid

Movement by itself is not made terminal by this task.

A unit may move partially, be deselected/reselected if the existing whole-side
scheduler permits it, continue legal movement, and then perform its terminal
action.

Do not break the accepted whole-side-phase rule that ordinary deselection and
reselection preserves still-available unit capacity.

### 4. Reactions do not spend the defender's activation

Counterattack, first strike, retaliation, passive hooks, aura/status effects,
on-hit effects, and other reactionary/automatic resolution do not independently
mark their source unit's ordinary activation spent merely because they execute
during another unit's command.

A defender that counterattacks must retain whatever eligibility it had for its
own later activation, subject to death or other already-established mechanics.

### 5. Explicit non-terminal exceptions

Use the repository's existing action policy instead of hard-coding an
ability-name exception list.

In particular, `Action.consumes_action`,
`Action.free_action_for`, and `Action.resolved_consumes_action(actor)` already
express actor-dependent non-consuming actions. Preserve and use that policy if
it is the current authoritative path.

A successfully resolved active action for which
`resolved_consumes_action(actor) == false` must **not** terminate the actor's
activation.

The known corpse-eating/rat example is evidence that the exception mechanism is
necessary. Do not implement corpse targeting/eating itself if that executor is
not already present merely to demonstrate the exception. A synthetic action
fixture using the existing policy is sufficient.

### 6. Refusals do not consume the activation

An action that is rejected before successful execution does not terminate the
unit merely because the player attempted it.

At minimum preserve this for:

- dead/invalid target;
- unreachable melee target;
- ranged target out of range;
- no ammunition;
- unavailable/refused activated action;
- acting out of the active side;
- unknown/invalid command where applicable.

Do not decide the unresolved semantics of an action that passes validation,
starts execution, and then later fizzles for an as-yet-unimplemented semantic
reason. If such a boundary exists in current code and must be decided to finish
this task, stop and report it.

### 7. Existing refresh semantics remain authoritative

`ActionPoints.begin_round()` and accepted extra-turn refresh/grant paths remain
the mechanisms that can restore eligibility after a terminal action.

Do not clear once-per-round limiters during ordinary terminality or ordinary
re-selection. Do not change the established extra-turn limiter semantics.

Forced rest/rest behaviour must not regress. If rest is already terminal, keep
it terminal; do not redesign rest solely for this task.

## Implementation constraints

Do not solve the problem by separately zeroing fields in every UI handler if an
existing engine-level action-consumption/eligibility abstraction can express the

## Required deterministic coverage

Add tests on both oracle and live GDScript/model paths where corresponding
execution exists.

The test set must distinguish at least:

1. **move -> melee -> terminal**
   - movement/approach can occur;
   - attack resolves;
   - actor cannot then move or attack again in that activation;
   - same side can still activate another unit.

2. **move/history -> ranged -> terminal**
   - R8 evaluates live capacity before terminal clearing;
   - shot resolves;
   - actor cannot then move/shoot again.

3. **activated action -> terminal**
   - `resolved_consumes_action(actor) == true`;
   - successful action resolves;
   - subsequent ordinary command is refused/unavailable.

4. **explicit non-terminal action**
   - use existing `consumes_action` / `free_action_for` policy;
   - successful action resolves;
   - actor remains eligible;
   - do not require implementing a missing corpse-eating executor.

5. **counterattack is not terminal for defender**
   - defender reacts;
   - defender remains eligible for its own later activation if otherwise alive
     and unspent.

6. **refusal is non-terminal**
   - at least one melee/ranged refusal and one action refusal;
   - actor remains eligible.

7. **refresh**
   - a terminal actor becomes eligible after ordinary round refresh;
   - an accepted extra-turn refresh restores eligibility without incorrectly
     resetting once-per-round state.

Tests must check authoritative model state/eligibility, not only presentation.

For the manual tactical slice, add or update an integration/input test proving
that after a successful terminal command the UI/controller cannot issue another
ordinary command for that actor and can select another eligible friendly unit.
